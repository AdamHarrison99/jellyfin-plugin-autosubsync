Close substantial pieces of work with an explicit **Done** and **Not done** table — one row per item,
what it is and its state — instead of describing progress in paragraphs. Asked for on 2026-08-16
after several turns of prose summaries.

**Why:** the work runs across many files, harnesses and docs at once, and prose buries what is
still outstanding. The maintainer needs to see remaining items at a glance without rereading the turn.

**How to apply:** two short tables (or one with a status column). Put blocked/unverified items in
Not done with the reason, never omit them. Items only they can do — committing, releasing — belong in
Not done as theirs, not silently dropped. Keep it alongside, not instead of, the detail they need.
